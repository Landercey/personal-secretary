# 私人秘书 · 依赖清单
#
# 设计原则：能少一个是一个。用户在别人电脑上装东西时，每多一个依赖就多一个
# 出错的地方；而且这个项目要能在 4 GB 内存、十分钟内跑起来。

# ---------------------------------------------------------------------------
# 必需：QQ 接入
# ---------------------------------------------------------------------------
# NapCat 用反向 WebSocket 推消息过来，我们得有个 WebSocket 服务端接住。
# 自己用标准库手写一个也不是不行，但握手、分帧、掩码、心跳、关闭这些
# 边界情况很绕，写错了表现为"偶尔收不到消息"，极难排查。
# 这个库是纯 Python、无编译部分，装完约 1 MB。
websockets>=13.0

# ---------------------------------------------------------------------------
# 必需：界面
# ---------------------------------------------------------------------------
# 界面是 html/css/js，用 WebView2 渲染（Windows 10/11 自带，用户不用装）。
# 这两个包加起来约 900 KB —— 比起"界面好不好看"，这点体积很划算。
#
# 为什么不继续用 tkinter：它做不到"高级"—— 没有圆角、没有阴影、
# 没有平滑滚动。用户对旧版本的抱怨原话就是"界面太简陋"。
#
# 内存代价（实测）：窗口开着时多占约 400 MB，**关掉立刻还回去**。
# 后台收消息不需要界面，所以常驻内存不受影响。
pywebview>=6.0
pythonnet>=3.0

# ---------------------------------------------------------------------------
# 必需：繁简归一
# ---------------------------------------------------------------------------
# 识别规则（"点""明天""周"）都是按简体写的。群里转发和语音转写常带繁体，
# 不归一会导致时间全部解析失败（实测「明天早上11點打遊戲」被算成 09:00）。
# 没装也不影响其它功能，只是繁体的那部分内容时间会认错。
zhconv>=1.4

# ---------------------------------------------------------------------------
# 可选：第 5 步（文件解析）会用到
# ---------------------------------------------------------------------------
# pypdf>=6.0            PDF 取文字层
# pypdfium2>=4.0        扫描件 PDF 渲染成图片（再交给系统 OCR）
# （Word / PPT / Excel / 图片都不需要装东西：Office 用标准库解析，
#   图片走 Windows 系统自带 OCR）

# ---------------------------------------------------------------------------
# 可选：本地视觉模型（读手写、黑板照片上的字）
# ---------------------------------------------------------------------------
